## 1. 项目概述

### 1.1 项目定位

面向全国户外运动俱乐部的 SaaS 化小程序解决方案。通过"统一后台 + 小程序皮"的技术架构，实现千个俱乐部千种面孔的商业拓展，帮助俱乐部快速建立数字化服务能力，同时为技术提供方（我方）建立可复用的平台级产品。

### 1.2 商业模式

| 产品类型 | 配置方式 | 定价 | 说明 |
|---------|---------|------|------|
| 独立小程序 | 带参数二维码（club_id） | 2000元/年 | 专属域名、品牌视觉、完整功能 |
| 共享小程序 | 不带参数 | 1000元/年 | 共享入口，俱乐部信息聚合展示 |

**竞品定价对比**：

| 竞品 | 定价模式 | 年费区间 | 定价区间 |
|-----|---------|---------|---------|
| 成行啦 | 年费+人头费 | ¥1,980/年 + ¥0.99/人 | 中等 |
| 火星平台 | 抽佣模式 | 35%抽佣 | 较高 |
| 三体云动/勤鸟 | SaaS年费 | 几千-几万元 | 较高 |
| 有赞 | SaaS年费 | 几千-几万 | 中高 |
| 两步路 | 免费+抽佣 | 免费，3%服务费 | 低 |
| **我们（定位）** | 年费制 | ¥1,000-2,000/年 | **中等偏下，有竞争力** |

**定价合理性分析**：
- **轻量工具定位**：相比成行啦的¥1,980/年，我们的独立版¥2,000定价持平，共享版¥1,000更低价
- **避免高抽佣**：火星平台35%抽佣模式对俱乐部利润侵蚀大，我们采用固定年费模式更友好
- **低于健身SaaS**：三体云动、勤鸟等健身SaaS价格几千-几万，我们定位轻量化更实惠
- **分层定价**：基础版覆盖小微俱乐部，高级版服务有更高需求的俱乐部

**核心价值主张**：
- 俱乐部方：低门槛数字化转型，0技术成本拥有专属小程序
- 技术提供方：一次开发，多客户复用，边际成本趋近于零

### 1.3 竞争差异化定位

**市场空白发现**：根据竞品调研，目前没有哪个产品同时做好「多俱乐部管理 + 千人千面 + 免责签署 + 知识分享」，这是我们的差异化机会。

| 差异化维度 | 竞品现状 | 我们的机会 |
|-----------|---------|-----------|
| 多俱乐部管理 | 成行啦无、两步路无、健身SaaS仅限连锁 | ✅ 支持多层级俱乐部架构 |
| 千人千面 | **所有竞品均无** | ✅ 核心差异化，N种面孔 |
| 免责签署 | 成行啦无、两步路无、健身SaaS有但不完善 | ✅ 合规免责+法律保障 |
| 知识分享 | 游侠客有但非SaaS、两步路弱 | ✅ SaaS化PGC知识沉淀（不做UGC社区） |
| 轨迹导航 | 仅两步路有 | ⚠️ 可延后实现 |

**差异化策略**：

1. **功能差异化**：聚焦竞品未覆盖的四个核心能力
2. **场景差异化**：专注户外垂直场景，避免与通用健身SaaS正面竞争
3. **价格差异化**：中等偏下定价，比健身SaaS便宜，比工具类产品功能更全
4. **服务差异化**：强调SaaS化部署快、维护成本低

### 1.4 技术选型

| 层级 | 技术方案 | 说明 |
|-----|---------|------|
| 小程序端 | 微信小程序 + WebView | 主体框架，样式参考"火星"户外小程序 |
| H5渲染层 | Vue3 + Vant | WebView 内嵌页面，实现跨端复用 |
| 后台管理 | Vue3 + Element Plus（RuoYi-Vue内置） | PC端管理后台，基于若依框架 |
| 后端服务 | SpringBoot + MyBatis（RuoYi-Vue） | 基于若依框架，代码生成器快速开发 |
| 数据库 | PostgreSQL | JSONB 原生支持，俱乐部配置存储更灵活 |
| 缓存 | Redis | Session、限流、热点数据缓存 |
| 文件存储 | 阿里云OSS / 腾讯云COS | 图片、视频、合同文件存储 |
| 支付通道 | 微信支付（WxJava SDK） | 活动缴费、分账、退款 |
| 消息通知 | 微信模板消息 + 订阅消息 | 用户通知 |

**关键技术决策**：

1. **框架选型：RuoYi-Vue（官方版）**
   - 若依官方维护，社区最大，文档最全，AI辅助生成代码成熟
   - 内置完整的RBAC权限体系（角色→菜单→按钮→数据权限），直接支撑多俱乐部权限隔离
   - 代码生成器大幅提升CRUD开发效率，适合一周出MVP的节奏
   - 数据权限机制扩展 club_id 行级过滤，实现轻量多租户，无需独立Schema或多实例部署

2. **多租户方案：共享数据库 + 行级隔离**
   - 所有业务表增加 club_id 字段，查询自动按俱乐部过滤
   - 利用若依「数据范围」机制扩展，按 club_id 控制数据可见性
   - 俱乐部个性化配置存储在 club 表的 JSON/JSON 字段中（主题色、Logo、名称等）
   - 单实例部署，低成本运维，符合客户"一两百块服务器"的预期

3. **WebView 方案**
   - 业务逻辑统一在H5维护，样式迭代无需审核发布
   - 支持 club_id 参数注入 + CSS 变量实现俱乐部个性化皮肤热更新

4. **数据库选型 PostgreSQL**
   - JSONB 原生支持，俱乐部个性化配置存储和查询性能优于 MySQL JSON
   - 若依可通过 MyBatis 适配 PostgreSQL，改动量不大（驱动+分页插件+部分SQL语法）
   - 开发者更熟悉，运维效率更高

#### 3.3.2 退款规则设计

> **竞品参考**：参考成行啦的退款机制，完善退款规则设计

**退款政策配置**（俱乐部可在后台自定义）：

| 时间节点 | 默认退款比例 | 说明 |
|---------|------------|------|
| 活动开始前7天及以上 | 100% | 全额退款 |
| 活动开始前3-7天 | 80% | 扣除20%作为违约金 |
| 活动开始前1-3天 | 50% | 扣除50%作为违约金 |
| 活动开始当天 | 0% | 不退款 |
| 俱乐部取消活动 | 100% | 全额退款，俱乐部承担 |

**特殊情况的处理**：
- **不可抗力**：因恶劣天气、政府管制等不可抗力取消活动，全额退款
- **保险理赔**：用户已购买保险且符合理赔条件，引导走保险流程
- **名额转让**：支持用户将名额转让给其他人（需管理员审核）

**退款金额自动计算**：
```
示例：活动费用100元，活动前2天申请退款
- 基础费用：100元
- 退款比例：50%（活动前1-3天）
- 退款金额：100 × 50% = 50元
- 系统自动计算，无需人工核算
```

**候补递补机制**：
- 有人退款后，名额立即释放给候补名单
- 候补用户按排队顺序自动递补
- 递补成功后发送通知，用户需在24小时内完成支付
- 超时未支付则取消候补资格，释放给下一位

| 条款确认 | 用户阅读后勾选确认，不能略过 | P0 | MVP必须 |

| 电子签章 | 手写签名或一键签署 | P2 | 可简化实现 |

> ⚠️ **重要提示**：根据竞品调研，各家免责协议做法差异大，法律上不能完全免责。建议找律师过模板，不能简单化处理。

#### 3.4.2 合规性设计说明

> **法律合规要点**（基于竞品调研和法律专业人士建议）

1. **免责协议的法律性质**
   - 免责协议本质上是"风险告知+知情确认"，不能完全免除人身损害责任
   - 协议中不能包含"无论任何情况均不负责"等绝对免责条款
   - 有效的免责协议应当：充分告知风险、获得知情同意、明确双方权责

2. **核心合规要素**（必须包含）
   ```
   免责协议结构
   ├── 活动固有风险告知
   │   ├── 户外活动不可预见的风险（天气、地形等）
   │   ├── 可能的受伤类型及后果
   │   └── 风险发生概率说明
   ├── 参与者健康声明
   │   ├── 身体健康状况确认
   │   ├── 无不适宜参与疾病的声明
   │   └── 既往病史告知（如有）
   ├── 装备准备确认
   │   ├── 已阅读装备清单
   │   └── 具备必要装备的承诺
   ├── 紧急情况授权
   │   ├── 紧急联系人信息
   │   └── 紧急情况下授权领队采取必要措施
   ├── 保险信息
   │   ├── 保险购买记录
   │   └── 保险覆盖范围说明
   └── 个人信息授权
       ├── 身份证号用于购买保险
       └── 紧急联系人信息使用授权
   ```

3. **签署合规要求**
   - **必须阅读**：用户必须滚动阅读至条款底部才能勾选（不能略过）
   - **字号规范**：正文字号不小于12px，重点条款加粗显示
   - **未成年人**：需监护人额外签署或确认
   - **签署记录**：记录签署时间戳、IP地址、UserAgent、条款内容哈希
   - **版本控制**：条款更新后需用户重新签署

4. **展示合规要求**
   - 条款内容不能过小或过于隐蔽
   - 重点免责条款应突出显示（如使用红色标注）
   - 用户确认前应展示完整条款摘要
   - 建议在条款开头增加"请您仔细阅读以下条款"提示

5. **合规性验证清单**
   ```
   ☐ 使用律师审核过的协议模板
   ☐ 协议内容不能包含绝对免责表述
   ☐ 签署过程记录完整可追溯
   ☐ 用户必须完整阅读才能签署
   ☐ 未成年人有特殊处理流程
   ☐ 条款更新有通知和重签机制
   ☐ 紧急联系人信息完整获取
   ☐ 保险信息明确告知
   ```

#### 3.4.3 核心业务流程

    ↓

    ↓

    - 标准户外免责文本（平台统一提供）

| 提现申请 | 俱乐部发起收入提现 | P2 | V2.0实现 |

#### 4.4.2 核心业务流程

**支付流程**：
```
用户提交报名
    ↓
后端创建订单（状态：待支付）
    ↓
调用微信支付统一下单接口
    ↓
返回支付参数（prepay_id）给前端
    ↓
前端调用 wx.requestPayment()
    ↓
用户完成支付
    ↓
微信回调通知后端（支付成功）
    ↓
更新订单状态：已支付
    ↓
发送模板消息通知用户
```

**分账流程**：
```
活动结束（或到达约定时间）
    ↓
统计该活动所有订单
    ↓
计算分账金额：
    - 平台收入 = 总金额 × 45%
    - 俱乐部收入 = 总金额 × 55%
    ↓
调用微信分账接口
    ↓
分账成功：更新账单状态
    ↓
发送通知给俱乐部
```

## 5. 千人千面/多租户设计

> 🟢 **核心差异化**：根据竞品调研，**所有竞品均无千人千面功能**。这是我们的核心差异化，是与成行啦等工具类产品的本质区别。

### 5.1 设计目标

实现"一个后台 + 一个小程序 + N种面孔"的商业目标，每个俱乐部拥有独立的视觉展示和运营能力，同时共享底层技术服务和数据通道。

**竞品对标**：

|-----|-------------|----------|------|

| 两步路 | ❌ 无 | ❌ 无 | C端工具 |
| 健身SaaS | ⚠️ 仅连锁 | ❌ 无 | 通用管理 |
| **我们** | ✅ 支持 | ✅ **核心差异化** | SaaS多租户 |

## 8. 风险点与注意事项

### 8.1 技术风险

| 风险点 | 影响 | 应对措施 |
|-------|-----|---------|
| WebView性能 | H5页面加载慢，体验差 | 做好首屏优化，合理使用缓存，考虑预加载 |
| 微信支付资质 | 需微信支付商户号 | 提前申请，了解个人/企业资质要求 |
| 小程序审核 | 首次审核可能不通过 | 提前了解审核规范，准备好资质材料 |
| 高并发 | 活动报名高峰期系统压力 | 做好接口限流，异步处理非核心逻辑 |
| **社区功能审核风险** | 社区/UGC类功能审核门槛高、需额外资质 | **已主动规避**：不做UGC/社区/社交功能，纯PGC展示模式 |

### 8.2 竞品竞争风险

| 风险点 | 影响 | 应对措施 |
|-------|-----|---------|
| **成行啦先发优势** | 成行啦已有200+俱乐部用户，品牌认知度高 | 强调差异化（千人千面、多俱乐部管理），不正面竞争 |
| **有赞生态优势** | 有赞百万商家，生态成熟 | 专注户外垂直场景，提供更专业的功能 |
| **两步路流量优势** | 两步路800万用户，社区活跃 | 差异化B端SaaS定位，不做C端流量竞争 |
| **大厂入场** | 阿里/腾讯等大厂可能切入 | 快速占领细分市场，建立护城河 |

**竞争策略**：
- 不与成行啦正面竞争价格战，差异化定价（功能vs工具）
- 不与大厂比资源，专注服务质量
- 快速迭代，响应用户需求

### 8.3 业务风险

| 风险点 | 影响 | 应对措施 |
|-------|-----|---------|
| **免责条款法律效力** | 条款是否被法院认可 | ⚠️ 见8.5详细说明 |
| 退款纠纷 | 用户要求退款被拒引发投诉 | 明确退款规则，保留沟通记录 |
| 活动安全问题 | 户外活动意外事故 | 必须购买保险，明确免责声明 |
| 俱乐部跑路 | 俱乐部收款后不组织活动 | 平台资金监管，分账延时 |
| **定价竞争** | 竞品可能降价竞争 | 提供差异化功能，不打价格战 |

### 8.4 合作风险

| 风险点 | 影响 | 应对措施 |
|-------|-----|---------|
| 分成比例争议 | 收入计算不透明引发矛盾 | 系统自动计算，定期对账，透明公示 |
| 客户流失 | 合作方或俱乐部终止合作 | 合同明确数据归属，做好数据备份 |
| 技术依赖 | 过度依赖我方技术能力 | 文档完善，知识沉淀，降低单点依赖 |

### 8.5 免责协议合规风险（详细）

> ⚠️ **重要风险提示**：根据竞品调研，各家免责协议做法差异大，法律上不能完全免责

**核心风险点**：
1. **不能完全免责**：免责协议本质上是"风险告知+知情确认"，不能完全免除人身损害责任
2. **条款效力存疑**：自行编写的条款可能不被法院认可
3. **格式要求严格**：电子签署需满足法律规定的形式要件

**风险等级评估**：
| 风险类型 | 风险等级 | 可能后果 |
|---------|---------|---------|
| 条款无效 | 高 | 发生事故时无法援引免责 |
| 格式不合规 | 中 | 电子签名法律效力存疑 |
| 告知不充分 | 高 | 仍需承担相应责任 |

**必须执行的措施**：
```
☐ 找律师审核并出具标准模板（必须）
☐ 俱乐部补充条款需再次审核
☐ 签署过程需记录完整（时间戳、IP、设备信息）
☐ 定期更新条款版本
☐ 购买专业责任险作为补充保障
☐ 建立事故应急预案
```

### 8.6 定价竞争风险

| 风险点 | 影响 | 应对措施 |
|-------|-----|---------|
| 竞品降价 | 成行啦等可能降价竞争 | 提供差异化功能，不打价格战 |
| 免费工具冲击 | 两步路等免费模式 | 强调SaaS服务的稳定性和功能完整性 |
| 价格战利润压缩 | 价格战导致利润下降 | 聚焦服务质量，提高客户粘性 |

**定价优势维持策略**：
- 不主动降价，通过差异化功能维持溢价
- 提供分层定价，满足不同客户需求
- 强调服务质量和技术支持

### 8.7 特别注意

1. **免责条款不是"一句话"能解决的**
   - 虽然客户说"AI一句话就能实现"，但免责条款涉及法律效力
   - 必须使用经过法律顾问确认的模板
   - 俱乐部可补充条款，但必须保留基础免责部分
   - 签署记录必须完整、可追溯

2. **MVP 要真的"M"**
   - "一周出七七八八"意味着MVP要极度精简
   - MVP只做：活动展示 → 报名 → 支付 → 免责签署
   - 其他功能全部后置，不要在MVP阶段贪多

3. **支付合规性**
   - 微信支付分账需要开通"分账"功能
   - 个人小微商户可能无法实现自动分账
   - 需要提前确认合作方的资质和账户类型

4. **数据归属**
   - 合同中明确约定各方的数据归属
   - 俱乐部数据属于俱乐部，但平台可汇总分析
   - 用户数据需要符合微信隐私政策

5. **技术债务预警**
   - WebView方案长期看可能有性能瓶颈
   - 如果项目发展好，后期可考虑原生小程序重构
   - 当前阶段保持架构可扩展，避免过度设计

### 11.2 我们的定价策略

**定价定位**：中等偏下，有竞争力

| 版本 | 定价 | 功能定位 | 目标客户 |
|-----|------|---------|---------|
| 共享版 | ¥1,000/年 | 基础功能 | 小微俱乐部、试用客户 |
| 独立版 | ¥2,000/年 | 完整功能 | 中型俱乐部 |

- ✅ 比成行啦¥1,980持平或更低
- ✅ 比健身SaaS几千-几万便宜很多
- ✅ 避免火星平台35%高抽佣
- ✅ 提供免费试用期

### 11.3 定价竞争优势

1. **分层定价**：满足不同规模客户需求
2. **无抽佣**：比火星平台35%抽佣更友好
3. **无额外费用**：不收人头费、活动服务费
4. **免费试用**：降低客户决策门槛
